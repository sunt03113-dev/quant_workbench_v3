## 一、结论：**不是遗漏，是条件不满足**

| 项 | 值（通达信原始数据） |
|---|---|
| 股票 | 688037 芯源微（科创板，属 20cm 宇宙） |
| 该股首条日线 | 20191216；末条 20260922；共 1640 条 |
| 20200117 位置 | 第 **24** 个交易日（**不是**上市前 5 日无涨跌幅限制窗口，该窗口为 20191216~20191220） |
| 20200117 OHLC | 开 92.00 / 高 109.80 / 低 89.00 / 收 **102.80** |
| 前收（20200116） | **94.00** |
| 涨停价（20%，科创板适用） | 94.00 × 1.2 = **112.80** |
| 是否封死涨停 | **否**（收 102.80 ≠ 112.80，最高 109.80 ≠ 112.80）；标量口径 10%/20% 双 False，与向量口径一致 |
| 成交额 | 6.673 亿元 = 近 20 日**最大**（`is_amtmax=True`） |
| 最高价 | 109.80 = 近 20 日**最高**（`is_highmax=True`） |
| 前 5 日涨停 | 20200116（当日 78.33 → 94.00，涨停价 93.996 → 94.00，收=高=涨停价，**封板**） |

**因此**：

1. 对任何要求「末锚点（D-0 / T_2 / T_last）必须涨停」的规则，**20200117 不可能成为信号日** —— 它当天根本没涨停。这是它不出现的第一原因。
2. 对 `121_r1_v1` / `111b_r1_v1` 这类 **10cm（沪深主板）** 规则，还有第二层原因：**688 科创板根本不在池内**（`_collect_stock_files("10cm")` 只收 600/601/603/605 + 000/001/002/003）。
3. 反过来，在 20cm 规则下芯源微是有命中的：`strategy_c1789895695594_r1_v1`（D-0 涨停+成交额 20 日最大；D-1 非涨停）中该股命中 **7 次**（2020-01-16、2020-01-22、2021-07-05、2021-11-11、2022-02-23、2024-10-08、2026-01-07）。注意 20200117 也**不符合**该规则 —— 因为它的前一日 20200116 恰好是涨停，而规则要求 D-1 非涨停。

## 二、七项能力逐条判定（用现有封装系统实测）

| # | 问题 | 判定 | 实际依据 |

| 2 | 能否使用当前正式规则 | ✅ **可** | `store.get_rule(stem)["strategy"]["plan"]` 直接取回正式 plan，`run_plan` 直接执行 |

## 三、真实失败项与最小补丁（只有真失败才提）

**结论：没有任何一项失败到需要新增接口、结论码表或新 Skill。**

两个「不顺手但可用」的小缺口，均**建议暂不补**（等第二次真用到再说，避免动冻结区）：

| 缺口 | 现状 | 最小补丁（若将来要做） | 建议 |

## 四、M4 侧可行性（同一路径可复用）

诊断路径依赖「本机 Python + app/skill 模块 + vipdoc」，三者在 M4 部署包里都已具备：
`deploy/bootstrap.sh setup` 会建 venv 并装依赖，代码包含 `app/`、`skill/`，行情包含 `appdata/market`。
所以 **M4 上的 WorkBuddy 可以用同一份 `probe_core.py` 思路做同等诊断**，不需要后端新增接口。
（纯 HTTP 方案不够用：`/api/backtest/{stem}/candidates` 只给结果表的输出列，给不出未命中日的原始 K 线与窗口极值。）
