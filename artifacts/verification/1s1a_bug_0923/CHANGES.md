# 2026-09-23 区间语义裁定（方案A）—— 变更记录

## 一句话
规则原文里 `D-1` 与 `D-x` 写了**同一组条件**时，工作台原先只校验两个端点；现改为
**`D-x~D-1` 整段区间每一天都必须满足该组条件**（kk 2026-09-23 裁定「方案A 区间式」）。
这是**识别层语义缺口**的修复，不是执行器算错数。

## 为什么要改（现象 → 根因）
- 现象：1S1A（`strategy_c1790145091328_r1_v1`）274 行，kk 参考 `0923_backtest.xlsx` 只有 131 行；
  点名的 `603156 @ 2026-05-18` 尤其离谱。
- 复核：A(274) ⊃ B(131)，**共同 131 行逐字段零差异**；多出的 143 行 = 112 主板 + 31 创业板。
- 根因：`603156 @ 2026-05-18` 的整理区间 `D-6~D-1 = 2026-05-08 ~ 2026-05-15` 里，
  **2026-05-13 是封死涨停**（前收 43.02 → 涨停价 `43.02 × 1.1 = 47.322 → 47.32`，当日最高=收盘=47.32，严格封死），
  另有 05-12 / 05-14 创 20 日新高。工作台只校验 `D-x(05-08)` 与 `D-1(05-15)` 两个端点，故放行。
  （D-0 自身 2026-05-18 封死涨停 `46.78 × 1.1 = 51.458 → 51.46` 是**规则要求**的条件，核验正确。）
- 证据：`ROOT_CAUSE.md`、`interval_check.txt`、`raw_recheck.txt`、`x_distribution.txt`。

## 改了什么（计划语言 + 执行器 + 识别器）
1. **计划语言新增「区间条件」**：`strategy_plan.ranges = [{"from": {"var": 0}, "to": -1,
   "conds": {...}, "label": "D-x~D-1"}]`。语义：对每个 x，令 `d_from/d_to` 为端点距 D-0 的深度
   （`{"var": k}` → `x+k`；`int off` → `-off`），区间日 `j = i-d_from … i-d_to`（含两端）
   **每一天**都满足 `conds`。
2. **执行器**（`app/executor.py`）：新增 `_range_pref` / `_range_depths` / `_range_ok`，
   用每日满足掩码的前缀和做 O(1) 区间判定；固定日路径与变量日路径都接入。
   - **fail-closed**：区间条件含 20 日窗口原子（成交额/最高价）时，窗口不足 20 日的日子一律判
     「不满足」（不可判定 ≠ 满足）——与 kk 参考实现 `cand[:x+23]=False` 同效。
   - 固定日路径收到变量端点 = 计划矛盾，直接抛错（不静默当成 D-0）。
3. **识别器**（`app/recognizer.py`）：
   - **显式写法**：`D-x~D-1：全部不是涨停，成交额不是最大，股价不是最高` → 直接生成区间条件。
   - **自动升级（方案A 核心）**：变量日规则里若 ① 存在 `x∈[a,b]` 声明；② 同时声明了固定 `D-1`
     与变量 `D-x`；③ 二者解析出的条件**完全相同且非空**；④ 输出段存在以 `D-x` 为一端的区间指标
     —— 则把 `D-1` / `D-x` 两条单日条件合并为 `D-x~D-1` 整段区间条件。
     任一条不满足即保持端点式（保守方向）。
   - 识别回执显式声明：`事件 D-x~D-1(整段区间每一天：非涨停，成交额非20日最大，最高价非20日最高（已按区间语义翻译）)`，
     并在 `plan_summary.notes` 给出同样说明（可审计，非隐式）。
4. **复核**（`validate_rows`）：新增 `_check_range_scalar`，由「D-0 日期 + x」重建区间位置后
   **逐日独立重验**（不复用向量化掩码），并新增 `RANGE_*` 违例码与 `RANGE_WINDOW_INVALID`。
5. **质询口**（`app/ask.py`）：「结果条件核验」类回答会把区间条件单列一行，避免漏述整段语义。
