# 0921A 语义修正 + 符号体系扩展（2026-09-21）

## 用户报告
0921A 规则回测结果与老系统正确基准（0921A_backtest.xlsx，299 行）完全不一致；
系统输出（111B_回测结果.xlsx，405 行）与其**零交集**。

## 根因（两个缺陷叠加）
1. **识别器**：条件行 `D-(x+2)：涨停…` 括号记号未被 `_day_offset` 的变量日分支
   捕获（只认 `d-x` 开头），落入 `d-` 兜底后被 `re.search(r"\d+")` 抓走括号内
   第一个数字 → `D-(x+2)` 被错解成**固定日 D-2**。整条规则实际回测成另一条规则。
   确定性复核器消费同一错误计划 → 假阴性 0 违规（复核是 plan 驱动，不比对规则原文）。
2. **出行口径**：golden 实证 x 取**最小满足值**、每个（股票，日期）只出一行
   （299/299 全中）；原实现「每个满足的 x 各出一行」。

## 修复
- `app/recognizer.py`（备份 git 基线）：
  - `_day_offset` 支持 `D-(x)` / `D-(x+k)` / `D-(x-k)` 括号变量日；
  - 输出区间分隔符 `~` 与 `~` 等价，保留用户书写习惯进列名
    （`_strip_annotations` 不再把 `~` 改写为 `/`）；
  - `D+1~D+8 价格走势` 输出列用 D+ 记号：`D+1(低/高)`、`D+2最高价`…；
  - T 体系 `-` 仅是标识符：`T-0/T-1/T-2` 与 `T_0/T_1/T_2` 等价
    （`_parse_chain_rule` 归一 + `_RE_CHAIN_TRIGGER` 认 `T[-_]?0`）。
- `app/executor.py`：
  - 量词出行默认 `mode="min"`（每 D-0 一行、x 最小满足）；plan
    `quantifier.mode="all"` 可切回逐 x 出行；
  - 列名对齐基准：`D-(x+2)振幅`、`D-x~D-1区间涨幅`（分隔符透传）。
- `ui/ui_v2.html`：预览/命中明细按首个「日期」列降序（时间倒序），
  兼容 `D-0日期`/`T_2日期` 等列名。
